# 角色与权限管理（RBAC）

- **状态：** Approved
- **审批记录：** 用户于 2026-10-20 确认本规格及全部 AC；批准进入 `sdd-plan`
- **版本：** 1.0
- **Spec ID：** IAM-RBAC-01
- **父 PRD：** [IAM 管理平台 PRD](../../prd/iam-management-platform.md)，FR-3、FR-4

## 结果与范围

平台管理员可管理角色及其权限；有用户管理权限的管理员可把一个或多个角色分配给员工；服务端根据用户所有角色的权限并集决定每个受保护操作是否允许。

**范围内**
- 固定权限目录、内置角色、自定义角色及角色权限关联。
- User 与 Role、Role 与 Permission 的多对多关系。
- 用户角色授予和撤销、最后一名平台管理员保护。

**范围外**
- 显式拒绝、资源级/属性级授权、权限条件表达式和租户级授权。
- 管理员自行创建或删除 Permission 目录项。

## 用户场景与验收条件

### UC-1 — 维护角色及其权限

作为 `PlatformAdmin`，我希望创建自定义角色并配置权限，以便按职责组合访问能力。

- **AC-1：** 权限目录只包含领域设计列出的稳定权限码；有 `roles:read` 的用户可查询目录，其他用户不能读取。
- **AC-2：** 有 `roles:write` 的 `PlatformAdmin` 可创建带唯一名称/代码的自定义角色，并把已知权限加入其中；重复名称/代码返回 `409`，未知权限被拒绝且不产生部分变更。
- **AC-3：** 可修改自定义角色名称、描述和完整权限集合；角色及 RolePermission 变更与对应审计事件原子提交。
- **AC-4：** 内置角色不得删除；自定义角色仍分配给任一用户时删除返回 `409`；可删除且未分配的自定义角色可以删除。
- **AC-5：** 没有相应权限的请求返回 `403`；未认证请求返回 `401`；拒绝请求不改变角色或权限关系。

### UC-2 — 为员工分配一个或多个角色

作为 `UserAdmin`，我希望分配允许范围内的角色，以便员工拥有完成职责所需的权限。

- **AC-6：** 用户与角色是多对多关系；同一用户可同时拥有多个角色，同一角色可授予多个用户，同一对关联最多存在一条。
- **AC-7：** `UserAdmin` 可查询角色并分配/撤销已存在的非 `PlatformAdmin` 角色；重复分配和重复撤销为幂等操作。
- **AC-8：** `UserAdmin` 不能授予或撤销 `PlatformAdmin`；只有 `PlatformAdmin` 可以管理该角色，未授权操作被拒绝且保留原分配。
- **AC-9：** 系统不得停用最后一名活动 `PlatformAdmin`，也不得撤销其 `PlatformAdmin` 角色；违反时操作失败且状态不变。
- **AC-10：** 角色或权限关系变更在下一次受保护请求即生效；系统不依赖登录时永久缓存的权限快照。

### UC-3 — 根据 RBAC 执行访问判定

作为 API 调用方，我希望每次请求都按服务端的当前权限判定。

- **AC-11：** 有效权限等于用户所有有效角色权限的并集；没有明确允许权限时默认拒绝；首版不存在显式拒绝规则。
- **AC-12：** 授权由服务端从当前 `UserSession` 识别用户并读取有效权限；请求体、查询参数或路径中指定的操作者 ID 不得改变当前身份。
- **AC-13：** 未认证请求返回 `401`，已认证但无权请求返回 `403`；响应不泄露其他用户或权限配置的秘密数据。

## 约束或验证说明

- 首版权限码、内置角色和角色能力矩阵以 [领域设计权限边界](../../design/iam-domain.md#权限边界) 为唯一来源。
- UserRole、RolePermission 关联的持久化和审计遵守项目约定：ID 关联、应用层校验，不建立数据库外键；关键关联变更与审计在同一事务提交。
