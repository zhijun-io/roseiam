# 邀请与员工生命周期

- **状态：** Approved
- **审批记录：** 用户于 2026-10-20 确认本规格及全部 AC；批准进入 `sdd-plan`
- **版本：** 1.0
- **Spec ID：** IAM-USER-01
- **父 PRD：** [IAM 管理平台 PRD](../../prd/iam-management-platform.md)，FR-2、FR-8

## 结果与范围

获授权管理员可邀请员工；员工验证邮箱并设置密码激活账号；管理员可查询、维护姓名、停用和重新启用员工。停用立即切断访问并撤销所有会话。

**范围内**
- 邀请、重发、激活、用户查询、姓名维护、停用和重新启用。
- 邮箱规范化唯一、邀请令牌一次性和 72 小时有效期。
- 初始分配可选角色及最后一名平台管理员保护。

**范围外**
- 用户自助注册、邮箱变更、硬删除和批量导入。
- 自动从外部人事系统同步账号。

## 用户场景与验收条件

### UC-1 — 邀请员工

作为具备 `users:invite` 权限的管理员，我希望邀请目标邮箱加入企业。

- **AC-1：** 有效邀请请求规范化目标邮箱，并创建邮箱唯一的 `Invited` User 和关联 `UserInvitation`；用户未完成激活前不能登录。
- **AC-2：** 系统在邀请事务提交后异步向目标邮箱投递一次性邀请链接；令牌在 72 小时后失效，服务端只保存安全摘要。
- **AC-3：** 对已有 `Invited` 用户重发邀请时，旧邀请立即失效，新邀请重新获得 72 小时有效期；审计使用独立于首次邀请的动作名；已有 `Active` 或 `Disabled` 用户返回 `409`，不创建第二个 User。
- **AC-4：** 邀请创建、待激活 User、可选 Role 关联及相应审计事件按领域事务规则原子提交；邮件在提交后异步投递。邀请 API 返回 `201`，不等待 SMTP 结果；投递失败记录运维错误，不改变已创建资源响应。管理员可重新邀请同一邮箱，旧令牌会撤销。
- **AC-5：** 缺少 `users:invite` 权限时拒绝；拒绝操作不创建 User、UserInvitation 或 Role 关联。

### UC-2 — 接受邀请并激活账号

作为被邀请员工，我希望验证邮箱并设置密码，以便激活账号。

- **AC-6：** 提交有效且未使用/撤销的邀请令牌、非空密码和必填 `name` 后，关联 User 变为 `Active`，`emailVerifiedAt` 写入当前时间，密码以 Spring Security 编码器安全存储，邀请标记为已使用。
- **AC-7：** 邀请已过期、已使用、已撤销或令牌无效时拒绝激活；User 保持 `Invited`，不得建立会话。
- **AC-8：** 邀请令牌只使用一次；并发重复提交最多有一次成功，其余请求不得再次改变账号或凭据。

### UC-3 — 管理员工账号

作为有相应用户管理权限的管理员，我希望查看员工并维护其状态。

- **AC-9：** `users:read` 可分页查询员工列表并读取单个员工；响应不返回密码摘要、令牌摘要或会话 token。
- **AC-10：** 有 `users:write` 的管理员可修改 `name`；邮箱和稳定 ID 不可通过该操作修改；实际变更与审计事件原子提交。
- **AC-11：** 有 `users:disable` 的管理员停用活动用户后，用户状态变为 `Disabled`、全部活动 `UserSession` 撤销；此后每个受保护请求均被拒绝。
- **AC-12：** 有 `users:enable` 的管理员可将 `Disabled` 用户重新启用；被撤销的旧会话不会恢复，用户必须重新登录。
- **AC-13：** 不得停用最后一名活动 `PlatformAdmin`；违反时操作失败，账号状态和会话均保持不变。
- **AC-14：** 无对应权限的管理请求返回 `403`；资源不存在返回 `404`；失败操作不产生部分状态更新。

## 约束或验证说明

- 邮箱按去除首尾空白并转为小写后比较唯一；首版不支持邮箱修改。
- 关键用户状态和资料变更与审计事件同一数据库事务提交；SMTP 投递不属于数据库事务。
- 可选角色集合必须由 IAM-RBAC-01 校验；任何邀请输入都不能授予调用者无权授予的角色。
