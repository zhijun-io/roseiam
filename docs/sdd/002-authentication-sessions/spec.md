# 认证、密码重置与会话

- **状态：** Approved
- **审批记录：** 用户于 2026-10-20 确认本规格及全部 AC；批准进入 `sdd-plan`
- **版本：** 1.0
- **Spec ID：** IAM-AUTH-01
- **父 PRD：** [IAM 管理平台 PRD](../../prd/iam-management-platform.md)，FR-1、NFR-1、NFR-2

## 结果与范围

已验证邮箱且处于活动状态的员工可通过邮箱和密码登录 API，安全重置密码，并可登出当前会话。

**范围内**
- 邮箱密码认证、邮箱验证状态检查、密码重置请求与完成。
- 不透明 Bearer token、服务端 `UserSession`、空闲/绝对期限和登出。
- 密码摘要、一次性密码重置令牌和成功登录审计。

**范围外**
- 登录限流、失败次数锁定、密码强度/轮换规则、MFA、SSO、JWT 和 Cookie 登录。
- 自助邮箱变更。

## 用户场景与验收条件

### UC-1 — 使用邮箱和密码登录

作为已激活员工，我希望使用已验证邮箱和密码取得 API 会话。

- **AC-1：** 当邮箱已验证、User 状态为 `Active` 且密码正确时，系统创建一个 `UserSession` 并返回随机不透明 Bearer token、token 类型、`idleExpiresAt` 和 `absoluteExpiresAt`；后端只保存 token 摘要。
- **AC-2：** 当密码错误、邮箱未验证、User 为 `Invited` 或 `Disabled` 时，登录被拒绝，不创建会话；失败响应不返回密码、令牌或堆栈信息。
- **AC-3：** 成功登录与 `UserSession`、成功 `AuditEvent` 在同一数据库事务提交；审计写入失败时两者均不保留。失败登录仍拒绝认证并尝试写入失败审计事件；审计写入失败时记录运维错误。

### UC-2 — 使用受保护 API

作为已登录员工，我希望 API 确认我的会话和当前权限后才处理受保护请求。

- **AC-4：** 每个受保护请求都从 Bearer token 解析会话，并检查会话未撤销、未超过 15 分钟空闲期限或 8 小时绝对期限，同时检查 User 仍为 `Active`。
- **AC-5：** 缺少、未知、撤销或超时 token 返回 `401`；会话有效但缺少操作权限时返回 `403`。
- **AC-6：** 有效请求更新 `lastActivityAt` 和空闲期限，但不得延长固定的 `absoluteExpiresAt`。

### UC-3 — 登出当前会话

作为已登录员工，我希望结束当前会话。

- **AC-7：** 携带当前有效 Bearer token 调用登出后，该 `UserSession` 立即撤销；其后请求使用该 token 返回 `401`。
- **AC-8：** 重复登出已撤销 token 不会恢复会话或产生额外状态变化。

### UC-4 — 请求并完成密码重置

作为忘记密码的员工，我希望通过邮箱收到一次性链接并设置新密码。

- **AC-9：** 密码重置请求对未知邮箱、未验证邮箱和可重置账户返回相同 `202` 外部响应；只有已验证邮箱的有效账户会收到邮件，响应不暴露账户是否存在。
- **AC-10：** 有效密码重置令牌在 30 分钟内只能成功使用一次；过期、未知、已使用或已撤销令牌均拒绝，且不改变密码或 User 状态。
- **AC-11：** 完成密码重置后保存新密码的安全摘要、标记令牌已使用并撤销该用户所有活动会话；停用用户不会因此重新激活。
- **AC-12：** 新密码只要求非空并由 Spring Security 密码编码器处理；首版不添加密码长度、复杂度、历史密码或轮换限制。令牌明文不进入存储、日志、审计或错误响应。

## 约束或验证说明

- 成功登录和关键凭据状态更新遵循 [审计事务规则](../../design/iam-domain.md#审计与平台设置)；邮件发送属于外部副作用，不加入数据库事务。密码重置邮件在提交后通过异步监听器 best-effort 投递；邮件故障不改变通用 `202` 响应，记录运维错误且不自动重试。进程在事件处理前崩溃可能导致邮件未发送，用户可再次请求。
- 当前 API 对登录失败的错误码是否区分邮箱不存在、密码错误等未规定；实现应避免给出可用于枚举账号的差异化响应。
