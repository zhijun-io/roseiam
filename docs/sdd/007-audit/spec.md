# 审计事件与查询

- **状态：** Approved
- **审批记录：** 用户于 2026-10-20 确认本规格及全部 AC；批准进入 `sdd-plan`
- **版本：** 1.0
- **Spec ID：** IAM-AUDIT-01
- **父 PRD：** [IAM 管理平台 PRD](../../prd/iam-management-platform.md)，FR-7、NFR-3

## 结果与范围

授权审计员和平台管理员可追踪关键身份与管理事实，并按批准的字段查询只追加审计记录。关键业务状态与对应审计事件保持原子一致。

**范围内**
- 成功/失败登录、邀请/激活、密码恢复、用户资料/状态、角色/权限、平台设置变更和审计查询事件。
- 受控审计字段、查询过滤、分页、365 天保留和自动清理。
- 与关键状态变化/成功登录的同事务提交。

**范围外**
- SIEM 集成、合规报告、不可篡改外部归档和用户偏好变化审计。
- 审计事件更新或删除 API。

## 用户场景与验收条件

### UC-1 — 记录认证和管理事件

作为组织审计员，我希望关键操作留下可归因的记录，以便追踪账号及权限变化。

- **AC-1：** 系统记录登录成功/失败、邀请与激活、密码重置请求/完成、用户姓名与状态变更、角色/权限变更、平台设置变更以及审计查询。
- **AC-2：** 每条事件至少包含唯一事件 ID、发生时间、操作者（可空）、动作、目标类型/ID（可空）、成功/失败结果、请求 ID；附加 JSON metadata 仅限白名单字段。
- **AC-3：** 审计载荷、日志、错误响应不得包含密码、密码摘要、会话 token、邮件令牌、SMTP 密码、加密密钥或可重放认证材料；平台设置事件最多记录发生变化的字段名，不记录设置值。
- **AC-4：** 成功登录的 `UserSession` 创建和成功登录事件、关键管理状态变更和对应事件必须在同一数据库事务提交；事件写入失败时业务变更及会话创建回滚。
- **AC-5：** 失败登录仍返回认证拒绝并尝试持久化失败事件；事件持久化失败不得转为认证成功，必须产生可观测的运维错误。
- **AC-6：** 审计记录只追加；业务 API 不允许编辑或删除事件。UserSetting 偏好变更不写入首批审计。

### UC-2 — 查询审计记录

作为有 `audit-events:read` 权限的审计员，我希望筛选和读取事件。

- **AC-7：** 有 `audit-events:read` 权限的用户可分页读取事件，并按时间、操作者 ID、动作、目标类型/ID 和结果过滤；分页、可排序字段和过滤字段受白名单约束。
- **AC-8：** 可按事件 ID 读取单条事件；不存在时返回 `404`；无权时返回 `403`，未认证时返回 `401`。
- **AC-9：** 审计查询本身记录一次查询事件；该查询事件不再次触发审计查询事件，避免递归记录。查询事件只记录使用的过滤字段，不记录过滤值。
- **AC-10：** 事件在发生后至少可查询至 365 天保留期限；到期后由自动清理移除，不提供手动删除接口。

### UC-3 — 审计写入故障

作为系统所有者，我希望审计存储故障不会造成成功操作缺少审计的状态。

- **AC-11：** 关键业务状态变更或成功登录的审计写入失败时，事务回滚，调用方得到失败结果，不能留下无对应事件的成功变更或活动会话。
- **AC-12：** 失败登录的审计写入失败时仍拒绝认证，并通过不含敏感信息的运维错误信号报告故障。

## 约束或验证说明

- “关键业务状态变更”包括邀请/激活、密码重置完成、用户资料/状态、角色/权限和平台设置变更。
- 邮件发送是外部副作用，不属于数据库事务；审计事件与业务状态先按数据库事务一致提交，邮件交付重试按相应集成规格执行。
- 审计保留期固定为 365 天；备份归档、不可篡改存储和法规合规不在本首批承诺中。
