# Product Requirements Document: IAM 管理平台

- **状态：** Approved 1.1（B1 首批员工 IAM 范围；用户于 2026-10-20 批准）
- **版本：** 1.1
- **日期：** 2026-10-20
- **信息来源：** 用户在本次对话中的直接输入；未提供用户访谈、业务数据或现有流程资料。

## Overview

### 问题陈述

本项目的发起动机是练习 IAM 产品开发，并交付一个可运行的企业产品。公司员工是明确的目标用户，但当前没有证据表明某个具体企业已遇到身份管理问题，也没有确定的客户身份使用场景。因此，本 PRD 定义的是一个以员工身份与访问管理为核心的练习型产品提案，不代表已验证的市场需求。

### 方案摘要

提供一个供单个企业员工和管理员使用的前后端分离 IAM 后端 API。首批能力包括邮箱密码登录、邮箱验证、邮件邀请与密码重置、员工账号生命周期管理、基于 RBAC 的角色与权限管理、个人资料与个人设置、基础系统设置，以及审计记录和查询。本项目只实现后端，不实现前端；客户身份暂不纳入首批。

### 目标用户

| 用户 | 需求与场景 | 证据 / 状态 |
| --- | --- | --- |
| 企业员工 | 登录并维护自己的个人资料，使用获授权的功能 | 用户明确指定；具体业务任务尚未验证 |
| 平台管理员 | 管理用户、角色、权限和平台基础设置 | PRD 1.1 已批准的默认管理角色 |
| 用户管理员 | 管理用户生命周期和用户角色分配 | PRD 1.1 已批准的默认管理角色 |
| 审计员 | 只读查询审计记录 | PRD 1.1 已批准的默认管理角色 |
| 客户用户 | 暂无已知任务 | 用户明确表示当前没有具体任务；不进入首批范围 |

### 证据与假设

- **已确认输入：** 项目目的是练手，目标是可运行企业产品，目标使用者为公司员工；客户暂时没有具体任务；前后端分离，只实现后端；邮箱+密码、验证邮箱、邮件邀请/重置；不考虑登录限流和密码规则；采用 RBAC；组织为单个企业。
- **本轮默认建议：** 多角色权限并集、默认拒绝、无显式拒绝；内置四种角色；UserSetting 和 PlatformSetting 使用 `type` + JSON `value`；用户偏好含语言、时区、主题；平台设置含平台名称、默认语言、前端基础 URL 和 SMTP 配置（密码加密保存且不读回）；审计保留 365 天；API 使用可撤销的不透明 UserSession Bearer token；首位平台管理员通过一次性初始化邀请建立；主键默认 Long、不使用 UUID；关系字段使用 ID 且建表不添加外键约束；本地使用 Docker Compose 运行后端与 Mailpit。
- **证据限制：** 没有企业访谈、现有系统评估、业务量或合规要求材料。本 PRD 不代表市场验证或法规合规承诺。

## Goals & Success Metrics

### Goals

1. **G-1：** 交付可部署和可操作的员工身份与访问管理产品闭环。
2. **G-2：** 通过端到端实现练习 IAM 的用户管理、RBAC、会话安全和审计能力。

### 成功指标

| 目标 | 指标 | 当前基线 | 目标 | 时间 / 状态 |
| --- | --- | --- | --- | --- |
| G-1 | 管理员从创建员工账号到分配访问权限，员工登录并使用获授权功能，相关操作可在审计中查询 | 未建立 | 首批交付的端到端场景全部通过验收；具体场景在规格中定义 | 首批交付；目标待规格确认 |
| G-1 | 新环境部署和初始化的可重复性 | 未建立 | 按部署文档在干净环境完成安装、初始化和首次登录 | 首批交付；环境与验收方法待设计确认 |
| G-2 | 核心身份与权限行为的自动化验证覆盖 | 未建立 | 登录、拒绝未授权访问、停用账号会话失效、RBAC 判定和审计写入均有自动化验证 | 首批交付；细节待规格确认 |

### 非目标

- 首批不服务客户身份场景；没有具体客户任务前不扩展为 Customer IAM。
- 本项目不实现前端应用；首批只提供可供独立前端调用的后端 API。
- 首批不实现登录限流、失败次数锁定、密码复杂度或密码定期轮换策略。
- 本 PRD 不声称产品已满足任何特定法规、认证或企业采购要求；适用的合规范围尚未提供。
- 技术基线建议采用 Spring Boot、Java、Maven、Spring MVC、PostgreSQL 和模块化单体；具体部署拓扑与数据库 schema 属于后续技术设计。

## Scope

### 产品方向与首批范围

本 PRD 1.1 首批交付提案围绕单企业员工身份管理闭环：邮件邀请并验证邮箱、登录或重置密码、分配 RBAC 角色、使用个人资料/设置、查询审计记录，以及停用账号并撤销会话。仅交付后端 API，不实现前端。下面的需求注册表是需求唯一来源；此交付批次仅引用需求 ID。

### 不在首批范围

- 客户自助注册、客户组织/租户管理和客户身份生命周期。
- 外部身份提供商联邦登录、企业 SSO、多因素认证、SCIM 自动配置。
- 复杂授权策略、显式拒绝规则、资源级或属性级授权。
- 高级身份治理、认证合规报告和 SIEM 集成。

以上为已批准首批范围之外的候选能力；如需纳入首批，应修订 PRD 并重新审批，不代表这些能力永久排除。

### 关键用户流程

1. 管理员创建或邀请员工账号；员工完成激活并登录。
2. 管理员将权限配置到角色，再为员工分配一个或多个角色。
3. 员工访问功能时，平台按其角色权限作出允许或拒绝判断。
4. 员工在个人中心管理允许自助修改的资料；管理员维护首批必要的平台设置。
5. 平台记录关键认证与管理操作；有权限的审计员或管理员查询记录。
6. 管理员停用员工账号后，该账号的后续请求被拒绝，现有会话失效。

详细状态转换、字段、权限矩阵、错误处理和验收条件由后续 `sdd-design` 与 `sdd-spec` 定义。

### 产品级例外

| 场景 | 预期行为 | 相关需求 |
| --- | --- | --- |
| 账号已停用但仍有活动会话 | 后续请求被拒绝，活动会话失效 | FR-8 |
| 用户不具备目标操作权限 | 操作被拒绝，不因界面隐藏而绕过服务端权限判断 | FR-4 |
| 用户尝试访问审计查询能力但无相应权限 | 查询被拒绝 | FR-4、FR-7 |

### 集成点

- 邮件服务：通过 SMTP 发送邀请和密码重置邮件；SMTP 参数与前端基础 URL 由平台管理员在平台设置中维护。本地开发使用 Docker Compose 启动 Mailpit；首次启动配置用于种入初始设置。
- 独立前端：本项目只交付 API；部署时注入前端精确 origin 白名单，默认拒绝未配置来源。

### 数据要求

- 产品需要维护 User、UserInvitation、PasswordReset、UserSession、Role、Permission、UserRole、RolePermission、UserSetting、PlatformSetting 和 AuditEvent。
- `PlatformSetting` 和 `UserSetting` 以 `type` 与 JSON `value` 组织配置；当前 API 对外仍使用具名设置 DTO。
- 审计记录保留 365 天后自动清理；令牌只以摘要形式保存，不记录至日志或审计载荷。
